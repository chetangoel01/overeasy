# Gemini 3.7 Live Import Design

## Purpose

Make `google/gemini-3.7-flash` Ladle's sole default OpenRouter model, then test
the normal end-to-end recipe import pipeline once against four supplied TikTok
videos and one supplied Instagram post.

## User-visible behavior

- New recipe extractions and targeted verification calls use Gemini 3.7 Flash
  unless an operator explicitly overrides the model setting.
- Each supplied social URL follows the same acquisition, evidence gating,
  extraction, deterministic review, and targeted verification path used by a
  normal import.
- The live-test report shows the final recipe, review state and warnings,
  acquisition or extraction failures, latency, and attributable provider cost
  for each URL.

## Design

Change the checked-in `LADLE_OPENROUTER_MODEL_ID` default in application
configuration and the example environment file from Gemini 3.6 Flash to Gemini
3.7 Flash. Keep the existing explicit model override so operators and evaluation
tools remain reproducible.

Run each supplied URL exactly once through the existing worker/import entry
point. Preserve the per-import output as a local verification artifact, with
secrets excluded. Do not run other models, benchmark repeats, or automatic
retries beyond the pipeline's existing bounded transport retry policy.

## Error handling

Treat acquisition, evidence-gate, provider, schema, and review failures as test
results rather than silently substituting another model. Report partial evidence
and the terminal failure when it is safe to do so. A failed source may receive
only the bounded retries already implemented by its provider clients.

## Testing and verification

1. Add a failing configuration test for the Gemini 3.7 default.
2. Update the production default and example environment file.
3. Run the narrow configuration tests, static checks, and `git diff --check`.
4. Commit the verified model switch as a recoverable checkpoint.
5. Run each of the five URLs once and validate that any successful output matches
   the recipe schema and includes review metadata.
6. Write a concise verification report containing the outputs and measured
   latency/cost, with credentials and private headers removed.
