# September 8 HIG fixes and iPhone build

Implements the nine findings from the [screen audit](2026-09-08-ui-audit.md).
The audit and its 208 captures remain the historical baseline. This follow-up
records the resulting behavior and fresh verification evidence.

## Resolved direction

The cook approved explicit **Keep Editing / Discard Changes**, immediate closing
for unchanged forms, one sheet with Back for related steps, sections opening at
the top, and a **custom Apple button using Apple's approved artwork**.

## Changes

| Finding | Result | Main components |
| --- | --- | --- |
| 1. Servings clips at AX5 | Scrollable content, large detent at accessibility sizes, value and stepper stacked; Reset stays reachable. | RecipeMetadataBand / ServingsSheet |
| 2. Filled action contrast | Tomato, Orange, and dark Sage fills darkened to pass 4.5:1; Focus Next, destructive fills, editor pills, and Share Done use readable pairs. Pressed fills darken without fading labels. | LadleTheme, color assets, LadleComponents, FocusModeView, ShareConfirmationView |
| 3. Faint supporting text | Recipe facts and related supporting copy use opaque semantic secondary ink on content surfaces; light secondary ink is #505B64. | Detail, library cards, editor, import, nutrition, Health, shared components |
| 4. Watch AX5 action wrapping | Actions stack vertically at accessibility sizes; the overlay scrolls and has a darker ground for readable content. | WatchRecipePage |
| 5. Clipped sign-in controls | Provider controls size to available width and retain complete labels; error messages can grow. | SignInOptionsView |
| 6. Editor scroll carryover | Selecting a section recreates its scroll container at the top; selected sections expose the selected accessibility trait. | RecipeEditorView |
| 7. Unsaved-input loss | Native two-choice alert on Cancel, Close, Back, or sheet swipe for dirty editor, manual entry, and recovery drafts. Keep Editing retains input; Discard exits. | DiscardChangesConfirmation, RecipeEditorView, AddRecipeSheet, CorrectionNotesView |
| 8. Stacked sheets | Profile → Sign in, Nutrition → Health, and failed import → recovery push within their existing sheet; Back returns to the parent. | AccountSheet, AccountSignInView, NutritionView, HealthExportSheet, AddRecipeSheet, FailedImportSheet |
| 9. Apple branding | Unchanged official vector artwork, black on white, original logo padding, type at 43% of button height and trailing space at least 8% of width. System authorization remains underneath. | SignInOptionsView, AppleSignInLogo.imageset |

The palette retains the existing warm light surfaces. DESIGN.md's stale surface
hex values were corrected to match the assets; the surfaces themselves did not
change. The brighter Focus accent remains on progress/icons; it is not a
white-label button fill.

SwiftUI disables a sheet swipe but does not expose attempted dismissal. A small
presentation-delegate observer supplies that callback only while a form has
changes, then restores the previous delegate. It binds to the controller actually
presented as a sheet, walking past pushed recovery controllers that inherit a
presenter but do not own the sheet. The explicit alert is intentional:
iOS 26's compact confirmation menu omitted the Keep Editing action.

## Apple artwork and guidance

Downloaded September 8 from [Apple Design Resources](https://developer.apple.com/design/resources/),
[Sign in with Apple logo package](https://devimages-cdn.apple.com/design/resources/download/Logo-Sign-in-with-Apple.dmg).
The asset is the **Left-aligned / Black / Medium PDF**, copied without modifying
its 31 × 44 canvas or logo padding. A plain-text copy of the
[Apple Design Resources License](../licenses/Apple%20Design%20Resources%20License.txt)
is retained with the repository.

Provider controls grow with Dynamic Type only as far as the available width
allows while preserving the logo-to-type proportions and complete wording. This
is a deliberate constraint for branded single-line controls; content and errors
continue to use the user's full text size.

Guidance: [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility),
[Typography](https://developer.apple.com/design/human-interface-guidelines/typography),
[Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets),
[Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts),
[Sign in with Apple](https://developer.apple.com/design/human-interface-guidelines/sign-in-with-apple).

## Verification

- Baseline tests reproduced low contrast, unguarded editor cancellation,
  section scroll carryover, nested account navigation, and unreachable Reset at AX5.
- App unit suite: **580 executed, 1 intentionally skipped, 0 failures**. Includes
  light/dark contrast checks for all five accents, Focus/destructive fills and
  secondary text on the three content surfaces, plus Share renders.
- **22 distinct UI tests passed**: all 11 new HIG regression tests, all 9
  Profile tests, recipe scaling, and the primary Discover → Inbox → recipe →
  cooking journey. Both sheet swipe and explicit cancellation were exercised;
  recovery covered notes, pasted details, and manual drafts. A final dedicated
  pass also verifies swiping from a pushed recovery form keeps its draft.
- **22 fresh captures** cover the affected layouts, navigation, discard alert, Share
  confirmation, recipe detail, and cooking. See the
  [updated-screen gallery](captures/2026-09-08-hig-fixes/index.html).
- Full app and embedded Share Extension **Release build succeeded**, using the
  existing paid development team and production HTTPS backend configuration.
  Bundle signatures verified; host and extension both report **1.0 (20260908.1)**.
- Installed in place on **Chetan’s iPhone 17 Pro**, running iOS 27. The device's
  app inventory confirms **com.ladle.ios, 1.0, build 20260908.1**. No uninstall or
  container reset was performed. The initial launch request was blocked because
  the phone was locked; launch confirmation awaits unlock.

The unit suite's skipped test is the existing opt-in live App Attest device
check (`LADLE_LIVE_APP_ATTEST`); the app ships with attestation disabled. This
verification did not perform real provider sign-in or write to Apple Health.

Reproduce with the `LadleAllTests` scheme on an iOS 26.5 iPhone simulator:

```sh
xcodebuild test -project Ladle.xcodeproj -scheme LadleAllTests \
  -destination 'platform=iOS Simulator,name=Overeasy-HIG-Fixes' \
  -only-testing:LadleTests -only-testing:LadleUITests/HIGRegressionUITests \
  -only-testing:LadleUITests/ProfileSheetUITests \
  -only-testing:LadleUITests/RecipeScalingUITests \
  -only-testing:LadleUITests/StateScenarioUITests/testPrimaryJourneyCapturesInboxDetailAndCooking \
  -parallel-testing-enabled NO CODE_SIGNING_ALLOWED=NO
```

The run used an isolated simulator. Select any available iPhone simulator when
repeating it; the HIG tests set their own largest accessibility text size.
The verification run bundles were `/tmp/overeasy-hig-green-1.xcresult` (unit suite),
`/tmp/overeasy-hig-green-2.xcresult` (nine corrected interaction/layout tests),
`/tmp/overeasy-hig-green-3.xcresult` (final sign-in, Profile, scaling and cooking),
`/tmp/overeasy-hig-sign-in-final.xcresult` (default provider-button rendering),
`/tmp/overeasy-hig-sign-in-ax5.xcresult` (final AX5 provider-button rendering),
and `/tmp/overeasy-hig-dismissal-final.xcresult` (editor, manual entry, and pushed
recovery dismissal after correcting ownership of the sheet delegate).
Earlier mixed run bundles also retain the intermediate failures, which were
corrected before the final installation.
