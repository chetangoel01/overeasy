## Product and architecture state

Ladle ships as **Overeasy**, a SwiftUI and SwiftData iPhone recipe workspace.
It imports recipe links through the app or Share Extension, tracks parsing and
review states, stores structured recipes, supports editing and safe re-import,
and provides recipe and focus cooking modes with timers.

The normal app composition uses the FastAPI backend. The backend uses Celery,
PostgreSQL, Redis, private object storage, and a shared Caddy gateway. Import
workers try free source metadata and transcripts first, can download and
transcribe audio with Whisper, optionally inspect a thumbnail, use paid
transcript fallbacks when configured, and finally perform structured recipe
extraction.

The newest integrated work covers:

- the shared VPS gateway and its guarded rollback path;
- server-side transcript acquisition with media cookies propagated into the
  transcription path;
- separately controlled thumbnail analysis while multi-frame analysis remains
  disabled;
- cache bypass for safe recipe re-imports;
- acceptance of the server-assigned replacement-candidate ID in the iOS app;
- deployment, recovery, metrics, SSRF, budget, and regression coverage for
  those paths.

## Important decisions and cautions

- Keep `main` as the stable integration branch. Continue work on a `codex/`
  feature branch and make task-sized verified commits.
- Do not remove the staging access gate as part of routine follow-up. A
  production promotion still needs its own design and plan.
- Production blockers include final DNS, externally durable versioned object
  storage, off-provider database backups, TLS-protected data services,
  Apple/Google production identity, App Attest, tracing, provider rotation,
  and distribution signing.
- Safe re-import intentionally bypasses the extraction cache and preserves the
  existing recipe until a ready replacement is persisted.
- Secrets, provider responses, staging keys, and gateway generations must not
  be added to Git or copied into verification documents.
